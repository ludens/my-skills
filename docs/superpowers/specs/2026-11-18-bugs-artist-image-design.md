# bugs-track-info 앨범 아티스트 이미지 설계

**날짜:** 2026-11-18
**이슈:** #19

## 목적

음원 태그 작업 시 앨범 아티스트 이미지 URL이 필요할 때가 있다. 기본 조회는 가볍게 유지하고, 필요한 경우에만 플래그로 추가 요청해 이미지 URL을 얻는다.

## 사실 확인 (2026-11-18)

| 항목 | 값 |
| --- | --- |
| 샘플 아티스트 | `https://music.bugs.co.kr/artist/80327438` (유나) |
| 이미지 출처 | JSON-LD `MusicGroup.image` = `https://image.bugsm.co.kr/artist/images/1200/803274/80327438.jpg` |
| 이미지 크기 | 1200x1200, 앨범 커버와 같은 CDN |
| 앨범 아티스트 ID | 앨범 상세 기본정보 `아티스트` 행의 `/artist/{id}` 링크 |
| 추가 비용 | HTTP 요청 1회, 실측 0.1~0.2초 |

## 목표

- `--artist-image` 플래그를 켠 경우에만 아티스트 페이지를 요청한다.
- 이미지 URL을 `artist.image_url`로 출력한다.
- 대상은 곡의 대표 아티스트가 아니라 **앨범 아티스트**다.

## 비목표

- 이미지 파일 다운로드, 태그 임베드.
- 참여 아티스트 전부의 이미지 수집.
- 기본 조회 동작과 출력 형식 변경.

## 접근

1. **선택됨**: `album_meta()`가 앨범 아티스트 ID를 함께 반환하고, 플래그가 켜졌을 때만 그 ID로 아티스트 페이지를 1회 요청한다. 앨범 페이지는 한 번만 읽고 `Client.get()`·`jsonld()`를 재사용한다.
2. 아티스트 이미지 함수를 독립시키고 앨범 페이지를 다시 읽어 ID를 얻는다. 같은 정보를 두 번 받는다.
3. 스크립트 수정 없이 SKILL.md에 수동 절차만 적는다. 자동 수집이라는 기존 동작과 어긋난다.

## 결정

- 플래그 이름은 `--artist-image`, 기본값 꺼짐. 꺼져 있으면 `artist` 키 자체를 출력하지 않는다.
- 아티스트 ID는 앨범 기본정보의 `아티스트` 행 앵커에서 추출한다. 페이지 전체에서 첫 `/artist/`를 찾는 방식은 참여 아티스트를 잘못 고를 수 있어 쓰지 않는다.
- 출력 형태: `artist: {name, image_url, url}`. 값이 없으면 `image_url`은 `없음`.
- 아티스트 페이지 요청 실패는 전체 조회를 실패시키지 않는다. `image_url: "없음"`과 `notes` 경고만 남긴다.
- 이름·이미지는 벅스 페이지 값을 그대로 쓴다. 다른 소스로 보완하지 않는다.

## 검증

- 오프라인: 앨범 HTML에서 아티스트 ID 추출, 아티스트 JSON-LD에서 `image` 추출 단위 테스트.
- 실제 실행: 플래그 없음이면 `artist` 키 없음, 플래그 있으면 샘플 URL 기대값 일치.
- 기존 8개 테스트 회귀 없음.

## 리스크

| 리스크 | 대응 |
| --- | --- |
| 벅스가 아티스트 ID를 앨범 페이지에서 제거 | ID 없으면 이미지 조회 건너뛰고 `없음` + `notes` |
| 이미지 URL 만료·변경 | 조회 시점 URL을 그대로 출력, 저장하지 않음 |
| 옵션 요청이 봇 월에 걸려 전체 실패 | 예외를 잡아 경고만 남기고 핵심 필드는 유지 |
