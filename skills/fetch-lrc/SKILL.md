# fetch-lrc

음원 파일 옆에 같은 이름의 `.lrc` 사이드카를 만든다. 가사는 LRCLIB에서 가져온다.

싱크 가사(타임스탬프 있는 가사)만 저장한다. 타임스탬프를 새로 만들지 않고, 없는 가사를 지어내지도 않는다.

## 발동 조건

- "lrc 만들어줘", "싱크 가사 붙여줘", "make synced lyrics", "create LRC"
- 음악 라이브러리(Navidrome 등)에 가사 사이드카를 추가하려 할 때

## 하는 일

1. `ffprobe`로 제목·아티스트·앨범·재생시간을 읽는다. 태그가 없으면 파일명 `아티스트 - 제목`으로 대체한다.
2. LRCLIB `/api/get`으로 조회한다. 실패하면 `/api/search`에서 재생시간 ±2초 이내 결과를 고른다.
3. `syncedLyrics`가 있으면 검증 후 그대로 저장하고 끝낸다. 저장 전에 **LRCLIB 곡 길이와 파일 길이**를 비교한다(±2초).
4. `syncedLyrics`가 없으면 저장하지 않고 중단한다. 일반 가사(`plainLyrics`)만 있어도 저장하지 않는다.
5. 사용자가 `--lyrics`로 싱크 가사 파일을 주면 LRCLIB보다 우선한다. 타임스탬프가 없는 파일은 거부한다.

## 입출력

입력:

```
python3 sync_lrc.py <음원경로> [--lyrics <싱크가사파일>] [--out <출력경로>]
```

- 음원: `.m4a`, `.mp3`, `.flac` 등 ffprobe가 읽는 형식
- `--lyrics`: UTF-8 텍스트. `[mm:ss.xx] 가사` 형태의 타임스탬프가 있어야 한다
- `--out`: 생략 시 음원과 같은 폴더, 같은 파일명에 `.lrc`

출력:

- `<음원>.lrc` — UTF-8, LF, 줄바꿈으로 끝남
- 형식: `[mm:ss.xx] 가사` 또는 `[mm:ss.xxx] 가사`
- 기존 `.lrc`가 있으면 `<음원>.lrc.bak`으로 백업 후 덮어쓴다
- stdout 리포트: 곡 정보, 가사 출처, LRCLIB id, 줄 수, 출력 경로, 백업 여부, 경고

종료 코드:

| 코드 | 의미 |
|------|------|
| 0 | 저장 완료 |
| 1 | 입력/메타데이터 오류 |
| 2 | 싱크 가사 없음 → 아무것도 쓰지 않고 중단 |
| 3 | 타임스탬프 검증 실패 → 아무것도 쓰지 않고 중단 |
| 4 | 곡 길이 불일치(±2초 초과) → 다른 버전으로 보고 중단 |

## 검증 규칙

쓰기 전에 검사한다. 실패하면 파일을 만들지 않는다.

- 모든 타임스탬프가 단조 증가(같은 값 허용)
- 마지막 타임스탬프가 곡 길이 + 1초 이내
- LRCLIB 응답의 곡 길이와 로컬 파일 길이 차이가 2초 이내

곡 길이 비교가 유일한 타이밍 대조 수단이다. 줄별 오프셋은 재지 않는다. 길이가 맞으면 같은 버전으로 보고 LRCLIB 타이밍을 그대로 믿는다.

## 하지 않는 일

- **전사·강제 정렬(forced alignment) 없음.** 시간을 새로 찍는 도구를 쓰지 않는다. 정렬된 가사가 없으면 실패로 끝낸다.
- **싱크 가사가 없을 때 일반 가사를 저장하지 않는다.** 타임스탬프 없는 `.lrc`를 만들지 않는다.
- 음원 태그(`©lyr`)를 쓰지 않는다. 목적은 사이드카 `.lrc`다.
- 멜론·지니 등 폐쇄 사이트를 스크래핑하지 않는다.
- 없는 가사를 생성하거나 추측으로 채우지 않는다.
- 음원 파일 자체를 수정하지 않는다.

## 성공 판정

- 음원 옆에 `.lrc`가 생겼다
- 타임스탬프가 단조 증가하고 곡 길이를 넘지 않는다
- LRCLIB 곡 길이와 파일 길이 차이가 2초 이내다
- 가사 내용이 실제 곡과 일치한다
- 기존 `.lrc`가 있었다면 `.lrc.bak`에 원본이 남아 있다
- 리포트에 가사 출처와 줄 수가 찍혔다

싱크 가사가 없어 중단한 경우는 성공이 아니다. 사용자에게 "LRCLIB에 싱크 가사 없음"을 알리고, 준비한 `.lrc`가 있으면 `--lyrics`로 넘기라고 안내한다.

## 전제와 한계

- `ffprobe`가 필요하다(PATH 또는 `/opt/homebrew/bin/ffprobe`). 외부 Python 패키지는 쓰지 않는다.
- LRCLIB은 사용자 기여 DB다. 인기곡은 대체로 있지만 니치곡·라이브·편집본은 없다. 없으면 실패한다.
- LRCLIB 재생시간과 로컬 파일 재생시간이 다르면(라이브/편집본/리마스터) 길이 비교에서 걸러 저장하지 않는다. 걸러지지 않은 2초 이내 차이는 그대로 허용한다.
- LRCLIB 응답 언어는 DB에 등록된 원문 언어를 따른다. 번역 가사는 제공하지 않는다.
